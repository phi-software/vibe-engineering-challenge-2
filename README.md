# Vibe Engineering Challenge

## Challenge 001 — TaskForge Lite: CSV Processing Web App

> **We evaluate engineering outcomes, not typing speed.**

你需要借助 AI Coding Agent，在**约 60 分钟**内完成一个可以运行的 CSV 数据处理 Web 应用。用户上传文件，后端按指定规则处理数据，前端展示处理结果与失败原因。

本题面向大四本科生及即将毕业的计算机相关专业硕士，考察你如何把清晰的需求交付成真正可用的软件。**允许 100% 使用 AI 生成代码**，但你需要理解自己的实现，并能说明如何验证它。

## 1. 业务背景与目标

TaskForge Lite 是一个小型批量文本处理工具。用户从浏览器选择 CSV 文件，点击“开始处理”；前端将文件发送至后端，后端逐行转换或判定失败，并把逐条结果返回给页面。

你需要交付一个**真实的前后端闭环**，而不是只有静态页面或预先写好的 Mock 数据。

**本次不要求**用户登录、多租户、异步队列、后台 Worker、任务进度推送、持久化、失败重试或幂等机制。这些是之前完整 TaskForge 版本的需求，**不属于本次 60 分钟挑战**，不应影响评分。

## 2. 必做需求

### 2.1 CSV 上传和解析

前端提供文件选择入口和“开始处理”按钮，将用户选择的 `.csv` 文件上传到后端。文件第一行必须包含 `id,text` 表头；每一条数据行是独立记录。

示例：

```csv
id,text
1,  hello world  
2,AI coding
3,[FAIL] simulated error
4,"hello,world"
```

要求：

- 使用正规的 CSV 解析方式；双引号包裹的字段中允许包含逗号及转义双引号，不可简单按逗号拆分。
- `id` 作为**字符串**原样保留，允许重复，不要求唯一。
- 保留 `text` 原始内容，在处理规则中再进行 Trim。
- 文件不能为空，必须包含表头及至少一条数据行。
- 文件可以包含额外列；本题只处理 `id` 和 `text`。

### 2.2 文本处理规则

后端按下表**从上到下**判断，命中一条即停止继续判断该记录：

| 顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | `text` 为空或 Trim 后为空 | `FAILED`，提供可读错误原因 |
| 2 | Trim 后字符数 **超过 200** | `FAILED`，说明超出长度限制 |
| 3 | 原始 `text` 包含区分大小写的 `[FAIL]` | `FAILED`，说明触发失败标记 |
| 4 | 其他情况 | `SUCCESS`，输出 Trim 后转换为大写的文本 |

说明：

- Trim 的空白判断以 JavaScript `String.prototype.trim()` 为参考。
- 字符数按照 **Unicode code point** 计算，而非字节数或 UTF-16 编码单元；恰好 200 个字符为有效长度。
- 为保证多语言后端评测公平性，**大写转换的验收数据使用 ASCII 文本**；Unicode 测试主要验证字符长度和空白处理。
- 单条记录失败**不能使整份文件的处理失败**，其余行仍应正常处理。
- 每条记录都需要返回状态、原始 `id`、原始 `text`、成功输出或失败原因。

### 2.3 后端 API

为了方便统一验收，**本题固定一个核心接口**：

```http
POST /api/process
Content-Type: multipart/form-data
```

上传字段名为 `file`，内容是 CSV 文件。有效 CSV 返回 `200` 和 JSON；至少包含以下结构（允许增加字段）：

```json
{
  "total": 3,
  "success": 2,
  "failed": 1,
  "records": [
    {
      "id": "1",
      "input": "  hello  ",
      "status": "SUCCESS",
      "output": "HELLO",
      "error": null
    },
    {
      "id": "2",
      "input": "[FAIL] bad",
      "status": "FAILED",
      "output": null,
      "error": "包含 [FAIL] 标记"
    },
    {
      "id": "3",
      "input": "hello,world",
      "status": "SUCCESS",
      "output": "HELLO,WORLD",
      "error": null
    }
  ]
}
```

`total`、`success`、`failed` 为整数，且 `success + failed = total`。`records` 顺序与 CSV 数据行一致；`status` 仅使用 `SUCCESS` 或 `FAILED`。成功记录的 `output` 为字符串、`error` 为 `null`；失败记录的 `output` 为 `null`、`error` 为可读字符串。

以下输入应返回 `400` 和包含**非空 `error` 字符串**的 JSON，不应伪造成功结果：

- 未上传文件或文件内容为空；
- CSV 无法正确解析；
- 缺少 `id` 或 `text` 表头；
- 只有表头、没有数据记录。

**注意：** 单条记录的 `text` 不合法时，该行返回 `FAILED`，但整份 CSV 仍返回 `200`，不是 `400`。

其他 API 可以自行设计，但不是必做要求。

### 2.4 React 页面

至少实现一个页面，支持：

1. 选择 CSV 文件并提交到真实后端 API。
2. 展示处理中的 Loading 状态。
3. 显示 `total / success / failed` 统计。
4. 按行展示 `id`、原始内容、状态、输出或失败原因。
5. 上传失败或接口返回 `400` 时显示可理解的错误信息。
6. 再次选择文件后可以重新处理并更新页面结果。

可以自由使用 Ant Design、MUI、Tailwind CSS、shadcn/ui 等组件库。**不要求**登录页面、任务历史、路由系统、响应式动画或复杂设计。

## 4. 公开验收场景

评审会使用不同于示例的数据执行这些**已公开规则**，不会以未说明的新功能作为必做项。

| ID | 场景 | 预期 |
| --- | --- | --- |
| T01 | 上传包含正常行、`[FAIL]` 行和带引号逗号的 CSV | 返回逐条结果，统计正确，页面可查看 |
| T02 | `text` 前后带空白 | 输出为 Trim 后的大写结果，`input` 保留原文 |
| T03 | 空值、全空白、超长文本和 `[FAIL]` | 分别得到 `FAILED` 及相应错误原因，不影响其他行 |
| T04 | 200 与 201 个 Unicode code point | 200 个不因长度失败，201 个因长度失败 |
| T05 | 一行同时满足长度超限和 `[FAIL]` | 按优先级报告长度超限 |
| T06 | 文件为空、缺少必需表头、只有表头或 CSV 格式错误 | API 返回 `400`，页面显示错误信息 |
| T07 | 相同 CSV `id` 在多行重复出现 | 每行保留并独立处理，不覆盖数据 |
| T08 | 连续上传两份不同 CSV | 第二次结果正确更新，不混入上一次的记录 |
| T09 | 通过浏览器完成选择、上传、结果展示 | 实际调用后端；有 Loading、结果和错误状态 |

自动化测试以 HTTP 行为和数据输出为准。页面布局只检查可用性与清晰度，不按视觉华丽程度评分。
